# Keputusan Desain Backend CODPO

Semua keputusan yang didelegasikan lewat prompt fase backend, beserta alasan.
Yang menunggu input kamu ditandai ⚠️.

| #   | Topik                               | Keputusan                                                                                                                                                                                                                                                                                                                                                                                                                     | Alasan                                                                                                                                                                                                                                    |
| --- | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Geo (PRD §46)**                   | PostGIS penuh: `geography(Point,4326)` + GiST index, radius via `ST_DWithin`, jarak via `ST_Distance`. Tidak ada haversine app-layer                                                                                                                                                                                                                                                                                          | Sesuai PRD; fresh start; akurat antar-benua; index-aware. Supabase mendukung `create extension postgis` langsung di migration                                                                                                             |
| 2   | **Auth method**                     | Email + password (Supabase Auth bawaan)                                                                                                                                                                                                                                                                                                                                                                                       | Gratis & langsung jalan tanpa konfigurasi SMTP/SMS. OTP via WhatsApp/SMS butuh provider berbayar (Twilio/WA BSP) — layak setelah MVP terbukti. Magic-link email bisa ditambah belakangan tanpa migrasi                                    |
| 3   | **Mode Buyer↔Seller (§6)**          | Flag `profiles.mode` yang bisa di-switch user sendiri, bukan role auth                                                                                                                                                                                                                                                                                                                                                        | Sesuai PRD: satu akun, dua mode. Role auth hanya `authenticated` + tabel `admin_users` untuk admin                                                                                                                                        |
| 4   | **Kompresi/thumbnail (§17)**        | CLIENT-SIDE sebelum upload (canvas/image-compression saat integrasi frontend); server hanya validasi mime+size di presign                                                                                                                                                                                                                                                                                                     | Server tidak memproksi binary → hemat CPU/egress; thumbnail = file kedua dari hasil kompresi client. Kalau kualitas client tak terkendali, upgrade path: Cloudflare Image Resizing on-top R2                                              |
| 5   | **Upload flow**                     | Presigned PUT URL (`/api/upload/presign`) → client upload langsung ke R2; DB simpan `object_key` saja                                                                                                                                                                                                                                                                                                                         | Efisien (prompt bagian D), binary tidak pernah lewat Vercel                                                                                                                                                                               |
| 6   | **BU expiry (§16)**                 | Dua lapis: guard **on-read** di semua query (`sale_type='BU' AND bu_expires_at>now()`) + **pg_cron** `expire_bu_listings()` tiap 10 menit untuk normalisasi data/reporting                                                                                                                                                                                                                                                    | On-read = tidak pernah bocor status basi walau cron mati; cron = data tetap bersih untuk admin/analytics. Cron lain: purge lokasi (hourly), expire sesi zombie (hourly), reminder COD (hourly)                                            |
| 7   | **Payment gateway boost**           | ⚠️ **BELUM ADA GATEWAY** — pembelian dicatat `listing_boosts.status='paid'` simulasi dengan harga snapshot. Struktur kolom sudah siap pending→webhook→paid                                                                                                                                                                                                                                                                    | Kamu belum memutuskan provider (kandidat: Midtrans/Xendit). Jangan asumsikan — tinggal swap flow di `purchase_boost` + tambah webhook endpoint nanti                                                                                      |
| 8   | **Retensi GPS (§31)**               | Titik disimpan hanya saat sesi aktif; maks **50 titik terbaru per user per sesi**; semua titik sesi selesai dihapus **24 jam** setelah ended. Throttle server-side: interval ≥30 detik DAN jarak ≥50 m (configurable di `app_config.gps`)                                                                                                                                                                                     | "Riwayat tidak disimpan berlebihan": last-known + checkpoint cukup untuk dispute. Purge via pg_cron + RPC `purge_my_locations(session_id)` yang **scoped ketat `user_id = auth.uid()`** — mustahil menghapus titik user lain di sesi sama |
| 9   | **Tracking stop otomatis (§31)**    | `post_cod_location()` MENOLAK update jika state ∉ {accepted..arrived} atau `sharing_enabled=false`; trigger transisi mematikan sharing + purge menyusul via cron                                                                                                                                                                                                                                                              | Client nakal tetap ditolak server-side, bukan cuma stop di frontend                                                                                                                                                                       |
| 10  | **Reputasi (§37)**                  | Materialized view `user_reputation` + refresh otomatis via trigger setelah review insert / trx update                                                                                                                                                                                                                                                                                                                         | Precompute, bukan agregasi per-request. Refresh non-concurrent supaya valid dalam transaksi trigger; swap ke CONCURRENTLY+cron kalau ukuran data membesar                                                                                 |
| 11  | **Rate limiting (§45)**             | Fixed-window in-memory per IP+scope (presign 30/mnt, message 30/mnt, cod-request 10/jam, review 10/jam, report 5/jam)                                                                                                                                                                                                                                                                                                         | ponytail ceiling: Map per-instance cukup utk MVP single-region. Multi-instance → Upstash Redis, API helper sama                                                                                                                           |
| 12  | **Authorization layering (§45)**    | Tiga lapis: (1) RLS Postgres untuk semua akses client-bound, (2) endpoint pakai **user-bound JWT client** sehingga query menghormati RLS, (3) mutasi multi-tabel/state-machine lewat **RPC security-invoker** yang cek role/partisipasi eksplisit di dalam DB. Service-role client HANYA untuk: views counter fire-and-forget, notifications mark-read (setelah scope `.eq(user_id)`), operasi admin (setelah `requireAdmin`) | RLS lapis pertama; logic kompleks (state machine, throttle) divalidasi sekali di satu tempat atomik; defense-in-depth seperti diminta                                                                                                     |
| 13  | **Privacy koordinat (§13)**         | Tabel dasar `listings.geom` presisi; publik hanya lewat view `listing_public` dengan `ST_SnapToGrid` ~110 m + `area_label`                                                                                                                                                                                                                                                                                                    | Alamat presisi tidak pernah terekspos anon; owner lihat miliknya penuh                                                                                                                                                                    |
| 14  | **Chat immutability**               | Tidak ada policy UPDATE/DELETE pada messages; system/cod_action message dibuat sistem, bukan client                                                                                                                                                                                                                                                                                                                           | Audit-friendly; quick actions §25 memicu state machine (endpoint COD), bukan pesan manual                                                                                                                                                 |
| 15  | **Endpoint testing tanpa frontend** | Semua endpoint menerima `Authorization: Bearer <supabase_jwt>` (bukan cookie) → curl/Postman langsung                                                                                                                                                                                                                                                                                                                         | Sesuai tuntutan testability; cookie-based tetap jalan untuk frontend karena proxy.ts refresh session                                                                                                                                      |
